# 作成メニュー レスポンシブUI実装指示

「作成」機能のUIをレスポンシブ対応してください。

PCでは「作成ボタン + ドロップダウン」、スマートフォンでは「Floating
Action Button（FAB）+ Speed Dial」として表示してください。

添付した参考画像のように、PCとスマートフォンで作成メニューの見せ方・操作方法を切り替えてください。

作成できる種類は以下の2種類です。

-   記録
-   購入記録

## 1. 基本方針

PCとスマートフォンで作成メニューのUIを変更してください。

-   PC：「＋ 作成 ▼」ボタンから開くドロップダウンメニュー
-   スマートフォン：画面右下に固定されたFAB（Floating Action
    Button）から上方向へ展開するSpeed Dial

画面サイズによって表示方式を切り替えてください。

User-Agentによる端末判定は使用せず、CSSのmedia
queryなど、viewportの幅を基準にレスポンシブ対応してください。

既存プロジェクトにbreakpointの共通定義が存在する場合は、新しく独自の値を定義せず、既存のbreakpointを優先して使用してください。

共通定義がない場合は、以下を目安にしてください。

-   768px未満：スマートフォン版
-   768px以上：PC版

## 2. PC版

PCでは、現在の「＋ 作成 ▼」ボタンを使用してください。

通常時：

``` text
┌─────────────┐
│ ＋  作成  ▼ │
└─────────────┘
```

「作成」ボタンをクリックすると、ボタンの直下にドロップダウンメニューを表示してください。

``` text
┌─────────────┐
│ ＋  作成  ▲ │
└─────────────┘
┌─────────────┐
│ 記録        │
│ 購入記録    │
└─────────────┘
```

### PC版の動作

-   「作成」ボタンをクリックするとメニューを開く。
-   開いている状態でもう一度クリックすると閉じる。
-   メニュー外をクリックすると閉じる。
-   メニュー項目をクリックすると閉じる。
-   Escapeキーでも閉じられるようにする。
-   開閉状態に応じて、必要であれば矢印アイコンの向きを変更する。

### PC版の配置

-   ドロップダウンは「作成」ボタンの直下に表示する。
-   原則としてボタンの左端とメニューの左端を揃える。
-   ドロップダウンを表示しても、周囲のレイアウトを押し下げない。
-   Popover、absolute配置などを使用し、既存UIの上に重ねて表示する。
-   他のコンテンツの裏側に隠れないようz-indexを適切に設定する。

### PC版メニュー

以下の順番で表示する。

1.  記録
2.  購入記録

各項目は文字部分だけではなく、メニューの1行全体をクリックできるようにしてください。

hover時には背景色などを変更し、クリック可能であることが分かるようにしてください。

## 3. スマートフォン版

スマートフォンではPC版の「＋ 作成 ▼」ボタンを表示しないでください。

代わりに、画面右下にFloating Action
Button（FAB）を固定表示してください。

通常状態では「＋」アイコンのFABを表示します。

## 4. FABの配置

-   FABは画面右下に固定する。
-   `position: fixed` 相当の配置にする。
-   ページをスクロールしても同じ位置に表示する。
-   画面端に密着させず、適切な余白を設ける。
-   iPhoneなどのsafe-areaも考慮する。
-   `env(safe-area-inset-bottom)` 等が利用できる場合は考慮する。
-   他のコンテンツより前面に表示する。
-   親要素のoverflowなどによってFABが切れないようにする。

## 5. FABをタップしたときの動作

FABの「＋」をタップするとSpeed Dialを展開してください。

Speed DialはFABから上方向へ展開します。

展開後は「＋」アイコンを「×」アイコンへ変更してください。

``` text
                  ┌────────────────┐
                  │ 🛒  購入記録   │
                  └────────────────┘

                  ┌────────────────┐
                  │ ✎   記録       │
                  └────────────────┘

                         ┌─────┐
                         │  ×  │
                         └─────┘
```

## 6. Speed Dial

Speed Dialには以下の2項目を表示してください。

-   記録
-   購入記録

FABに近い項目から、

1.  記録
2.  購入記録

の順番になるようにしてください。

つまり、画面上では上から「購入記録」「記録」「FAB」という並びになります。

### Speed Dialのデザイン

各項目はスマートフォンで押しやすい横長のボタン形式にしてください。

各ボタンには「アイコン + ラベル」を表示できる構造にしてください。

実際のアイコンについては、既存プロジェクトで使用しているアイコンライブラリがある場合はそれを使用してください。

絵文字をそのままUIに使用する必要はありません。

既存のアイコンライブラリに適切なものがある場合は、

-   記録：編集、ノート、ドキュメント等を表すアイコン
-   購入記録：ショッピングバッグ、カート等を表すアイコン

を選択してください。

新しいアイコンライブラリは、既存ライブラリで実現できない場合を除いて追加しないでください。

## 7. スマートフォン版の背景オーバーレイ

Speed
Dialを開いている間は、参考画像のように画面全体へオーバーレイを表示してください。

目的は、背景のコンテンツよりも作成メニューに視線を集中させることです。

レイヤー順は以下にしてください。

1.  Speed Dial / FAB
2.  オーバーレイ
3.  通常の画面コンテンツ

オーバーレイ表示中は、背景側のボタンやリンクが誤操作されないようにしてください。

オーバーレイ部分をタップした場合は、Speed Dialを閉じてください。

## 8. スマートフォン版の開閉動作

Speed Dialを開く：

-   「＋」FABをタップ

Speed Dialを閉じる：

-   「×」FABをタップ
-   背景オーバーレイをタップ
-   「記録」を選択
-   「購入記録」を選択
-   Escapeキーが利用可能な環境ではEscapeキー

## 9. アニメーション

Speed
Dialの開閉は突然表示・非表示を切り替えるだけではなく、軽いアニメーションを付けてください。

例えば、`opacity`、`translateY`、`scale`などを使用して、FABから上方向へ自然に展開するような表現にしてください。

過度なアニメーションにはしないでください。

OS/ブラウザで `prefers-reduced-motion: reduce`
が指定されている場合は、アニメーションを無効または最小限にしてください。

## 10. タップ領域

スマートフォンで操作しやすいようにしてください。

特にFAB、「記録」、「購入記録」は十分なタップ領域を確保してください。

文字だけがタップ対象になる実装にはせず、ボタン全体をタップできるようにしてください。

## 11. PC / スマートフォンで処理を共通化する

PC版とスマートフォン版は「表示方法だけ」が異なるものとして実装してください。

メニュー定義と選択後の画面遷移処理はPC /
スマートフォンで共通化してください。

例えば以下のような構成を検討してください。

``` ts
const createItems = [
  {
    type: "record",
    label: "記録",
    icon: ...,
    route: /* 既存の記録作成画面のroute */
  },
  {
    type: "purchase",
    label: "購入記録",
    icon: ...,
    route: /* 既存の購入記録作成画面のroute */
  }
];
```

実際のroute名やURLはこの例から新しく作成しないでください。

必ず既存コードを調査し、現在使用されているrouteを特定して使用してください。

## 12. コンポーネント設計

既存プロジェクトの設計・命名規則を優先してください。

必要であれば、

-   `CreateMenu`
-   `CreateDropdown`
-   `CreateSpeedDial`

などに責務を分けてください。

ただし、小規模な処理を必要以上に細かくコンポーネント分割する必要はありません。

既存コードの構成を確認し、最も自然な形で実装してください。

## 13. テーマ対応

既存のテーマ機能に対応してください。

ライトテーマ、ダークテーマなど、現在選択されているテーマに応じて、FAB、Speed
Dial、Dropdown、オーバーレイ、hover、focusの色が自然になるようにしてください。

既存のCSS変数やテーマ用トークンが存在する場合は、固定色を直接指定せず、それらを優先して使用してください。

## 14. アクセシビリティ

ボタンである要素は適切な`button`要素を使用してください。

キーボード操作やスクリーンリーダーも考慮し、

-   `aria-expanded`
-   `aria-haspopup`
-   `aria-label`

など、必要なARIA属性を設定してください。

フォーカス状態が視覚的に分かるようにしてください。

PC版ではキーボードでも作成メニューを操作できるようにしてください。

## 15. 既存機能への影響

今回の変更によって、既存の画面レイアウトや他の機能を壊さないようにしてください。

特に、

-   PC版のサイドバー
-   ヘッダー
-   メインコンテンツ
-   スクロール
-   スマートフォン版レイアウト

への影響を確認してください。

ドロップダウンやFABを追加するためだけに、既存画面全体の構造を大きく変更しないでください。

## 16. メニュー選択後の画面遷移

「記録」「購入記録」の作成画面は、すでに既存画面として実装されています。

**今回、新しい作成画面・フォーム・モーダル等は作成しないでください。**

作成メニューから各項目を選択した場合は、既存の作成画面へ遷移するようにしてください。

### 「記録」を選択した場合

PC版Dropdownまたはスマートフォン版Speed
Dialから「記録」を選択した場合は、既に実装されている「記録」の新規作成画面へ遷移してください。

新しい記録作成画面を作成するのではなく、既存コードを確認して以下を利用してください。

-   既存のroute
-   既存のrouter
-   既存の画面コンポーネント
-   既存の画面遷移方法

### 「購入記録」を選択した場合

PC版Dropdownまたはスマートフォン版Speed
Dialから「購入記録」を選択した場合は、既に実装されている「購入記録」の新規作成画面へ遷移してください。

こちらについても新しい画面を作成せず、既存のrouteおよび画面コンポーネントを再利用してください。

## 17. 画面遷移処理の共通化

PC版とスマートフォン版で、別々の画面遷移処理を実装しないでください。

-   記録 → 既存の記録新規作成画面
-   購入記録 → 既存の購入記録新規作成画面

という対応関係を共通で定義し、PC版Dropdownとスマートフォン版Speed
Dialのどちらから選択しても同じ処理を呼び出す構成にしてください。

同じメニュー定義やクリック処理をPC用・スマートフォン用に重複して記述しないでください。

## 18. 既存画面・ルーティングの調査

実装を開始する前に、既存コードを確認してください。

特に以下を調査してください。

-   現在の「作成」ボタンの実装場所
-   「記録」新規作成画面のコンポーネント
-   「記録」新規作成画面のroute
-   「購入記録」新規作成画面のコンポーネント
-   「購入記録」新規作成画面のroute
-   現在使用しているrouter
-   既存画面で使用している画面遷移方法
-   レスポンシブ対応方法
-   breakpointの定義
-   使用中のUIコンポーネント
-   使用中のアイコンライブラリ
-   テーマ/CSS変数の定義

既存のルーティング方法や画面遷移方法が存在する場合は、必ず既存の実装方法に合わせてください。

今回の対応のためだけに、別のrouterや独自の画面遷移方式を追加しないでください。

## 19. 実装してはいけないもの

今回の対応では、以下を新しく作成しないでください。

-   記録作成画面
-   購入記録作成画面
-   記録作成フォーム
-   購入記録作成フォーム
-   記録登録API
-   購入記録登録API
-   既存画面と同等の新しい画面
-   新しいルーティング方式

既に存在する画面・route・処理を再利用してください。

既存画面やrouteが見つからない場合は、推測で新しいものを作成せず、どの画面へ遷移させるべきか確認してください。

## 20. 今回の実装範囲

今回実装する範囲は以下です。

-   PC版の「＋ 作成」ボタン
-   PC版Dropdown
-   スマートフォン版FAB
-   スマートフォン版Speed Dial
-   スマートフォン版背景オーバーレイ
-   レスポンシブ切り替え
-   開閉処理
-   「記録」選択時の既存画面への遷移
-   「購入記録」選択時の既存画面への遷移

作成画面そのものは今回の実装対象外です。

## 21. 完了条件

### PC

-   「＋ 作成」ボタンが表示される。
-   クリックするとDropdownが表示される。
-   「記録」「購入記録」が表示される。
-   外側クリックで閉じる。
-   Dropdownによって既存レイアウトがずれない。
-   「記録」をクリックすると既存の記録新規作成画面へ遷移する。
-   「購入記録」をクリックすると既存の購入記録新規作成画面へ遷移する。

### スマートフォン

-   PC用「作成」ボタンは表示されない。
-   画面右下に「＋」FABが固定表示される。
-   FABがスクロールしても右下に固定されている。
-   FABをタップするとSpeed Dialが上方向へ展開する。
-   「＋」が「×」に変化する。
-   「記録」「購入記録」が表示される。
-   背景にオーバーレイが表示される。
-   オーバーレイをタップすると閉じる。
-   「×」をタップすると閉じる。
-   「記録」をタップすると既存の記録新規作成画面へ遷移する。
-   「購入記録」をタップすると既存の購入記録新規作成画面へ遷移する。
-   safe-areaを考慮している。

### 共通

-   PC / スマートフォンでメニュー定義を可能な限り共通化している。
-   PC / スマートフォンで画面遷移処理を共通化している。
-   既存の作成画面を再利用している。
-   不要な新規画面・フォーム・routeを作成していない。
-   既存のrouterおよび画面遷移方式を使用している。
-   既存テーマに追従している。
-   既存UIを壊していない。
-   TypeScriptの型エラーがない。
-   lint / build /
    testが用意されている場合は実行し、エラーがないことを確認する。

5.  「記録」の遷移先として使用した既存route

8.  実行したlint / build / testとその結果
